# Clarifications

### Session 2026-07-17

- **Q:** Which sizing scale SHALL be supported by the default implementation? → **A:** XS, S, M, L, XL, XXL.
- **Q:** Does the plugin implement an independent estimation algorithm? → **A:** No. It derives T-Shirt Sizes from the deterministic Story Point estimation.
- **Q:** Can organizations customize the mapping between Story Points and T-Shirt Sizes? → **A:** Yes, through Rule Packs.
- **Q:** Is T-Shirt Sizing intended to replace Story Points? → **A:** No. It provides a higher-level, lower-resolution representation of the same relative effort estimate.
- **Q:** How does the plugin access Story Points results in the pipeline? → **A:** Via a separate `TSHIRT_CLASSIFICATION_COMPLETED` pipeline event sequenced after `MEASUREMENT_COMPLETED`. Reads `ctx.measurement_result` (set by Story Points) before classifying.
- **Q:** What attributes should FunctionalWorkItem, TShirtSize, and MeasurementEvidence have? → **A:** Each item carries element_id, element_name, story_point_value, tshirt_size, mapping_rule, evidence_refs, applied_rule_pack — consistent with 024.
- **Q:** What happens when Story Points measurement results are unavailable? → **A:** Return empty result with warnings; pipeline continues.

# Overview

The T-Shirt Sizing Measurement Engine is a deterministic SpecMetrics plugin responsible for classifying functional work items into **relative effort categories** using the traditional T-Shirt sizing approach.

Unlike Story Points, which provide finer estimation granularity through the Modified Fibonacci sequence, T-Shirt Sizes intentionally reduce precision to improve communication, portfolio planning and early-stage estimation.

The plugin **does not perform an independent estimation process**. Instead, it consumes the deterministic Story Point estimates produced by the Story Points Measurement Engine and translates them into configurable T-Shirt Size categories.

The plugin performs no semantic inference.

---

# Objectives

The Measurement Engine SHALL:

- produce deterministic T-Shirt Size classifications;
- reuse Story Point estimates whenever available;
- preserve complete explainability;
- support organizational Rule Packs;
- integrate with the Measurement Plugin infrastructure;
- provide a simplified effort classification suitable for roadmap and portfolio planning.

# Classification Model

T-Shirt Sizing represents the **relative implementation effort** of a functional work item using broad categorical ranges.

The plugin SHALL classify every Story Point estimate into exactly one T-Shirt Size.

The default sizing scale SHALL be:

- XS
- S
- M
- L
- XL
- XXL

# Key Entities

## TShirtMeasurementResult

Complete classification output identified by pipeline run ID.

Contains:
- **method**: "TShirtSizing"
- **scale**: Size labels used (default: XS, S, M, L, XL, XXL)
- **items**: List of classified FunctionalWorkItem
- **distribution**: Count of items per T-Shirt size
- **applied_rule_pack**: Rule Pack identifier
- **warnings**: Non-fatal issues
- **execution_metadata**: Timing, counts, version

---

## FunctionalWorkItem

A Functional Process classified by relative effort.

Contains:
- **element_id**: UUID of the originating Functional Process
- **element_name**: Human-readable name
- **story_point_value**: The Story Point estimate consumed
- **tshirt_size**: Assigned T-Shirt Size (e.g., "M", "XL")
- **mapping_rule**: The rule that produced this classification
- **evidence_refs**: Provenance links to SP result and CFM
- **applied_rule_pack**: Rule Pack identifier used

---

## StoryPointEstimate

The deterministic estimate consumed by the plugin.

Contains:
- **value**: The Story Point value (integer from Fibonacci scale)
- **source_run_id**: Run ID of the Story Points measurement

---

## TShirtSize

Categorical representation of implementation effort.

Contains:
- **label**: Size label (e.g., "XS", "M", "XXL")
- **story_point_range**: The SP range that maps to this size
- **ordinal**: Position for sorting (1-based)

---

## MeasurementEvidence

References explaining the classification.

Contains:
- **element_id**: CFM node ID
- **story_point_value**: Originating SP estimate
- **mapping_rule**: Rule applied for this classification
- **document_id**: Originating document
- **section_id**: Originating section

## Rule Pack

External policy modifying classification mappings.

# Assumptions

- The Canonical Functional Model has already been validated.
- Story Point estimation has already been completed successfully.
- Rule Packs have been resolved before classification.
- Export plugins consume Measurement Results.
- T-Shirt Sizing is treated as an independent measurement methodology plugin that depends on the Story Points Measurement Engine.
- The default implementation uses the six-level scale (XS, S, M, L, XL, XXL), although organizations may customize both the scale and the mapping through Rule Packs.

---

# Implementation Notes

The T-Shirt Sizing Measurement Engine intentionally serves as a **presentation and aggregation layer** over the Story Points Measurement Engine rather than introducing a second estimation algorithm. This design guarantees consistency between both methodologies while allowing different stakeholders to consume the level of precision most appropriate to their needs. Development teams can continue working with Story Points for sprint planning, whereas executives, portfolio managers and product leaders can rely on T-Shirt Sizes for roadmap planning, investment discussions and high-level capacity analysis. Because the plugin derives its output directly from deterministic Story Point measurements, it preserves reproducibility, explainability and calibration while avoiding duplicated estimation logic within the SpecMetrics ecosystem.

> **Note:** This specification defines the **plugin architecture, deterministic classification model, Story Point dependency, explainability requirements and integration contracts** for T-Shirt Sizing. It intentionally treats T-Shirt Sizes as a higher-level representation of relative effort rather than an independent estimation methodology, ensuring consistency across all effort-based measurements within SpecMetrics.
